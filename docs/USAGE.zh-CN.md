# AstrBot 模型控制台 · 使用说明

一句话：这是一个跑在本机浏览器里的 AstrBot 配置工作台，用来查看和修改模型绑定（主对话模型、压缩模型、图片/语音模型、插件用模型与共享推理强度），每次保存前先备份、再预览确认；默认只读写 127.0.0.1，也可以通过 HTTP / SSH / Agent 三种方式查看远程设备。

> 适用版本：`package.json` 中的 `0.1.0`（开发基线）。具体行为以程序实际返回为准。
> 免责一句话：**保存成功只代表“已写入并回读一致”，不代表 AstrBot 已热加载、更不代表模型调用成功。**

## 1. 这个工具能做什么、不能做什么

### 1.1 能做的事

- 以卡片形式查看 AstrBot 的模型配置：全局 `default` 配置、各机器人实例使用的配置、插件配置、共享模型定义。
- 修改**已审查**的模型绑定字段，例如主对话模型、上下文压缩模型、图片描述模型、语音识别/合成模型、记忆向量与重排序模型、表情管理用模型等。
- 修改共享 provider 的**推理强度**（`custom_extra_body.reasoning_effort`），但只按 AstrBot 后端实际返回的能力目录放行。
- 先暂存草稿，再统一预览、逐资源保存；保存前自动备份，保存后回读校验，并写脱敏审计。
- 查看/清理/恢复本机备份；从备份恢复某个资源（整对象回写，恢复前先展示差异）。
- 连接远程设备查看配置：HTTP（OpenAPI Key）、SSH（本机 ssh 隧道）、Agent（同一程序的 Agent 模式配对）。
- 远程设备健康检查、诊断导出、首启向导、配置版本显示。

### 1.2 明确不做的事（请务必知道）

- **不代理模型生成**，不是模型网关；不新增 provider、不编辑 provider 的密钥/地址，也不改 AstrBot 的人格（persona）。
- **不创建、不删除** profile 或 provider；只修改上述已审查字段。
- **不重启 AstrBot**，也不直接覆盖 AstrBot 的数据库文件；保存走 AstrBot 自己的管理 API。
- **不保证热加载**。界面上显示“热加载已核实”必须有 Agent 端日志证据；本机保存只保证“写入 + 回读一致”。
- **不提供跨资源原子事务**。多个资源是逐个保存的，中途失败会停止，已保存的资源不会自动回滚。
- **不做线上状态监测**：`/health` 正常只说明控制台自己活着，不代表 AstrBot 或 QQ 在线。
- **远程默认只读**：HTTP / SSH 永远只读；只有 Agent 设备在两侧都允许时才可远程写。

## 2. 系统要求与获取方式

### 2.1 便携包（推荐给普通用户）

| 项 | 要求 |
|---|---|
| 操作系统 | Windows x64（便携包只提供 Windows 版本） |
| Node.js | **不需要安装**，包内自带 `node.exe` |
| 权限 | 普通用户目录即可，不需要管理员权限 |
| 安装器/自动更新 | 没有。解压即用，升级 = 替换整个目录 |

获取后解压到任意普通目录（不要放在 `C:\Program Files` 这类需要管理员权限的位置），会看到：

```
AstrBotModelConsole\
├─ node.exe
├─ start.cmd          ← 双击启动（编辑模式）
├─ package.json
├─ README.md
├─ SHA256SUMS.txt     ← 文件校验清单
├─ src\  public\  docs\
```

### 2.2 源码方式（开发/自用）

| 项 | 要求 |
|---|---|
| Node.js | `>=24.22`（见 `package.json` 的 `engines`） |
| 依赖 | 零第三方运行依赖，不需要 `npm install` |
| 操作系统 | 开发基线是 Windows；源码未在其他系统上做过完整验证 |

```powershell
cd <model-console 源码目录>

.\start-console-edit.cmd # 编辑模式启动并打开浏览器
```

> 仓库里只有 `start-console-edit.cmd` 一个开发启动脚本；便携包的 `start.cmd` 由构建脚本生成，不在源码目录里。

## 3. 启动控制台

### 3.1 便携包：双击 `start.cmd`

1. 解压便携包；
2. 双击 `start.cmd`（编辑模式，内部等价于 `--enable-writes --open`）；
3. 命令行窗口会显示本次会话的启动信息，浏览器会自动打开控制台；
4. **关闭这个命令行窗口即停止服务**；重新使用就再双击一次。

如果 `start.cmd` 提示 `node.exe is missing`，说明包不完整，重新解压或重新构建。

### 3.2 源码：`start-console-edit.cmd`

```powershell
cd <model-console 源码目录>
.\start-console-edit.cmd
```

它等价于：

```powershell
node src/server.mjs --enable-writes --open
```

- `--enable-writes`：允许“应用修改”。**它不会自动保存任何东西**，保存仍要在页面里预览并勾选确认。
- `--open`：让程序尝试用系统默认浏览器打开带本次令牌的地址（仅 Windows 生效）。

### 3.3 临时只读查看

```powershell
node src/server.mjs --open
```

不带 `--enable-writes` 就是只读模式：可以浏览配置、看设备与备份，但界面会禁用暂存/保存与恢复。适合“只想看看”，不建议日常使用。

### 3.4 启动输出怎么读

程序会打印一行 JSON：

```json
{"url":"http://127.0.0.1:PORT/#token=...","readOnly":false}
```

- `url` 里的 `#token=...` 是**本次工具会话令牌**，不是 AstrBot 的密钥；
- 浏览器打开后，页面会读取该令牌并立即清掉 URL 片段，令牌只保存在当前标签页的 `sessionStorage`（刷新仍在，关闭标签失效）；
- 如果浏览器没自动打开，把窗口里打印的 URL 手动复制到浏览器即可。
- **不要分享这条 URL 或令牌**。它只在本机回环地址有效，但拿着它就能操作这个控制台。

打开页面后若没有自动带上令牌（显示“连接本机控制台”），把启动窗口里的令牌粘贴进去点“连接”即可，**不需要填写 AstrBot 的 JWT / API Key**。首次连接成功且当前标签页没有向导完成标记时，会显示 3 步“快速开始”向导；随时可以跳过，它不修改任何配置。

## 4. 环境变量与路径

### 4.1 环境变量

| 变量 | 作用 | 默认值/说明 |
|---|---|---|
| `ASTRBOT_DATA` | 指定 AstrBot 的 `data` 目录 | 未设置时自动发现（见 4.2） |
| `MODEL_CONSOLE_STATE` | 指定控制台状态目录（备份/审计/诊断/设备/锁） | 默认 `%LOCALAPPDATA%\AstrBotModelConsole\state` |
| `MODEL_CONSOLE_PORT` | 固定监听端口 | 默认 `0`，由系统分配随机回环端口 |
| `MODEL_CONSOLE_SESSION_TOKEN` | 复用固定会话令牌（64 位小写 hex） | 仅受控重启场景使用；普通使用不要设 |
| `MODEL_CONSOLE_BACKUP_KEEP` | 备份保留份数 | 默认 `10`；清理时绝不动最新一份 |
| `MODEL_CONSOLE_BACKUP_MAX_MB` | 备份目录总大小上限（MB） | 默认 `2048`；超出删最旧并写诊断告警 |

PowerShell 临时设置（只影响当前窗口及其子进程，适合排查）：

```powershell
$env:ASTRBOT_DATA = 'C:\Users\你\.astrbot_launcher\instances\<实例ID>\core\data'
$env:MODEL_CONSOLE_STATE = 'D:\AstrBotModelConsole\state'
.\start-console-edit.cmd
```

### 4.2 AstrBot data 目录怎么找

本工具**不会猜**，查找顺序（见 `src/config.mjs`）：

1. 设置了 `ASTRBOT_DATA` → 直接使用该路径；
2. 否则扫描：
   - `%USERPROFILE%\.astrbot_launcher\instances\*\core\data`
   - `%USERPROFILE%\.astrbot\data`
3. 只有**恰好命中一个**目录才会自动使用；0 个或多个都会报 `ASTRBOT_DATA_REQUIRED`，按提示用环境变量指定。

> 目录判定：`data` 目录里应有 `cmd_config.json`。控制台只读这个目录，不会改写 AstrBot 程序本身。

### 4.3 状态目录里有什么

默认：`%LOCALAPPDATA%\AstrBotModelConsole\state\`（无 `LOCALAPPDATA` 时退到系统临时目录）。

| 文件/目录 | 内容 |
|---|---|
| `backups\<uuid>\` | 每次保存前的备份（配置 JSON + `data_v4.db` 拷贝 + `manifest.json`） |
| `audit.jsonl` | 写入审计（apply-start / applied / apply-failed，含备份路径，不含完整配置和凭证） |
| `diagnostics.jsonl` | 脱敏诊断日志（1 MiB 滚动，保留 3 份；不写 token/key/请求体/绝对路径） |
| `devices.json` | 已登记的远程设备（不含密钥） |
| `secrets.json` | 设备凭据，Windows 下用 DPAPI 加密为 `dpapi:<base64>` |
| `instance.lock` | 单实例锁（pid / 端口 / 启动时间） |
| `agent.json` | 仅当在本机运行 Agent 时出现：只存 token 的 sha256 与配对码 hash/过期时间 |

> 状态目录含备份、审计与设备凭据，**不要上传、不要提交 git、不要随程序目录一起分发**。
> 项目里若检测到旧的 `./state` 目录，只会打印提示，不会自动迁移或删除。

## 5. 界面导览

### 5.1 顶部栏与左侧导航

- **设备选择器**：本机 / 已登记的远程设备；选择会记在当前标签页的 `sessionStorage`。
- **配置版本**：来自 `default` 配置的 `config_version`，显示“未知”表示没读到。
- **模式胶囊**：`未连接` / `只读模式` / `允许保存` / `远程 · 只读` / `远程 · 可写`。
- **刷新配置**：手动重新读取；页面还提供“自动同步”（可见时约每 3 秒刷新，隐藏标签暂停）。
- **左侧导航**：`配置总览`、`AstrBot 本体`、`插件模型`、`模型库`，对应页面四个区。

### 5.2 配置总览

四个统计：可用模型、配置资源、模型绑定、异常引用；下方显示最近同步时间与“自动同步”开关。
工具条还有“搜索插件、用途或模型”和“只看异常”。

### 5.3 AstrBot 本体

- 先显示实际机器人实例卡片（来源是 AstrBot 的实例与平台级路由），再显示共享的 `default` 配置；
- 未被任何实例使用的配置档案会折叠进“未使用的配置档案”分组；
- 每张卡片里是“任务用途 / 使用模型 / 配置状态”表格，状态胶囊含义：

| 状态 | 含义 |
|---|---|
| 已配置 | 有值且模型存在、已启用 |
| 引用缺失 | 配置指向的模型不存在 |
| 模型禁用 | 指向的模型被禁用 |
| 字段不存在 | 配置里没有这个路径（区别于“有字段但为空”） |
| 跟随会话 | 该字段留空时按当前会话选择 |
| 待核实 | 有字段但为空，空值语义尚未核实 |

- 未审查字段不会出现在可编辑下拉里；卡片底部会提示“另有 N 个待审查字段；未核实前不开放修改”。

### 5.4 插件模型

每个插件一张卡片，展开后按“任务用途”列出该插件登记的模型绑定（例如群图片识别、记忆向量、记忆重排序、学习精炼等）。
向量/重排序这类字段会标注“切换需单独迁移索引”，**不能在本工具里直接切换**。

### 5.5 模型库

- 列出共享 provider 模型：启用状态、能力（文字/视觉/向量/重排序/语音识别/语音合成）、直接引用处数、当前推理强度；
- 点“调整推理强度”会向后端查询该模型支持的档位，只显示真实返回的档位；查不到就不允许随便填；
- 修改推理强度会作用于所有引用该共享模型的地方，卡片上会列出直接引用。

### 5.6 待应用变更（右侧面板）

- 选择模型时只是“暂存”，不会立即写入；
- 面板显示每条草稿的原值 → 新值，可单条移除、可“放弃全部修改”；
- “预览修改”会按资源分组生成计划并弹出确认对话框；跨资源修改是**逐个保存**，不是原子操作。

### 5.7 预览与确认

对话框里列出每个资源的改动、影响范围与警告，必须勾选“我已核对修改内容及共享影响范围”才能点“应用修改”。
应用失败会显示已完成数量和错误码；若结果不确定（`possibly-written`），界面会提示先核对配置与备份、不要直接重试。

### 5.8 冲突面板

刷新时发现配置已变（例如 AstrBot 面板或另一个工具改了），会显示“配置已被其他面板修改”，按“字段 / 我的值 / 服务器当前值”列差异：

- “稍后处理”暂时收起；
- “以最新值为基线重新编辑”会丢弃**该资源**的旧草稿并重新读取，**其他资源的草稿保留**。

### 5.9 备份与恢复

- 显示备份数量、占用空间、保留上限、容量上限；可设置“保留份数”后点“清理旧备份”（会二次确认）；
- 表格列出每份备份的时间、大小、文件数、数据库校验结果；
- 选中本机备份后可“查看差异” → “生成恢复计划” → 走同样的预览/确认/应用流程；
- 恢复**会覆盖所选资源的完整对象**（不只是差异字段），界面有明确警告；
- 远程设备的快照里备份只能查看，恢复仅在本机执行。

### 5.10 远程设备与提示条

表格：名称、类型（本机 / HTTP / SSH / Agent）、地址、健康、凭据是否已保存、删除。下方表单支持三种类型；右上角还有“导出诊断”按钮（下载脱敏诊断事件 JSON）和“刷新设备”。

- 远程只读/可写提示条会说明当前查看的是哪台设备、能否写入；存在会话级/通配符路由时（`routing.granular > 0`）会提示“卡片仅代表平台级视图”；
- 页脚提醒：状态来自配置声明与 API 回读，不表示上游调用成功。

## 6. 典型任务

### 6.1 修改某个机器人（或全局 default）的主对话模型

1. 确认顶部模式为 `允许保存`（或 `远程 · 可写`）；
2. 到“AstrBot 本体”，展开目标卡片；
3. 在“主对话模型”一行选择新模型（下拉只列已启用且能力匹配的模型）；
4. 右侧“待应用变更”出现草稿后，点“预览修改”；
5. 核对改动与影响范围，勾选确认，点“应用修改”；
6. 成功后页面提示“已保存并回读 N 个配置资源”，并自动刷新。

> “default 配置”是合法目标：使用全局默认配置的机器人，改的就是 `default`。

### 6.2 修改插件使用的模型

1. 到“插件模型”，展开对应插件；
2. 按用途选择模型（例如“记忆向量”“记忆重排序”会被标成需要单独迁移索引，界面不允许直接改）；
3. 其余步骤同 6.1。

### 6.3 调整推理强度

1. 到“模型库”，找到某个共享模型；
2. 点“调整推理强度”，选择后端真实支持的档位；
3. 确认影响范围（所有引用该模型的功能）后预览并应用。

### 6.4 一次保存多个资源

暂存多处修改后点“预览修改”，预览里会按资源分组；点“应用修改”后按资源顺序逐个保存。**任何一处失败就停止后续保存**，已完成的资源不会自动回滚。

### 6.5 从备份恢复某个资源

1. 到“备份与恢复”，点“刷新备份”，选择一份备份；
2. 选择资源类型与资源，点“查看差异”（只列已审查字段的差异）；
3. 点“生成恢复计划”，核对“会覆盖完整对象”的警告后确认应用；
4. 应用时仍会做版本双检、写前备份和回读验证。

### 6.6 连接远程设备

#### HTTP（OpenAPI Key）

1. 在“远程设备”表单选 `HTTP`；
2. 填名称、地址（远端 AstrBot dashboard 地址，如 `http://192.168.1.20:6185`）、OpenAPI Key（AstrBot 的 OpenAPI Key，通常以 `abk_` 开头）；
3. 添加后在顶部设备选择器切换过去即可查看，**只读**。

#### SSH（本机 ssh 隧道）

前置条件：运行控制台的这台机器上有 `ssh` 命令（Windows 可选功能“OpenSSH 客户端”），且已配置**免交互的公钥登录**（程序以 `BatchMode=yes` 运行，不会弹密码提示）。

1. 类型选 `SSH`；
2. 填地址：远端 dashboard 的 loopback 地址（`http://127.0.0.1:<远端 dashboard 端口>`）；端口可先占位，若填写了“远端数据目录”，程序会从远端日志 `Starting WebUI at ...` 自动发现真实端口；
3. 填 SSH 主机、端口（默认 22）、用户、私钥路径（可选，留空用 ssh 默认密钥/agent）；
4. 添加后在设备选择器切换，只读查看。

#### Agent（同一程序的远程 Agent 模式）

在目标机器上运行 Agent（只需 Node，或使用带 `node.exe` 的便携包）：

```powershell
# 目标机器：启动 Agent（默认只读；加 --enable-writes 才允许远程保存）
node src/agent.mjs --port=0 --state D:\AstrBotModelConsole-agent
```

- Agent 只监听 `127.0.0.1`，启动打印 `{"url":"http://127.0.0.1:PORT","pairingCode":"12345678","expiresAt":"..."}`；
- 配对码是**一次性 8 位数字，10 分钟有效**；配对失败过多会限频（5 次/分钟，返回 429）；
- 在 Hub（控制台）的“远程设备”里选 `Agent`，填名称、Agent 的 `url`、配对码；如需远程写，再勾选“允许远程写入”（前提是 Agent 端已 `--enable-writes`）；
- Hub 会把设备 token 保存到本机 `secrets.json`（DPAPI 加密），Agent 端 `agent.json` 只保存 token 哈希；
- Agent 默认只读；只读 Agent 的写入类接口会返回 403 `AGENT_READ_ONLY`。

#### 远程写与热加载证据

- 只有 **Agent 设备**、且 **Hub 勾选允许远程写入**、且 **Agent 以 `--enable-writes` 启动**，三者同时满足才可远程保存；HTTP / SSH 永远只读；
- 远程应用成功后，Agent 返回 `hotLoad` 证据对象：
  - `verified:true`：Agent 在本机 `logs/astrbot.log` 尾部（≤200 行）发现了重载标记（如 `reload`、`热重载`、`配置已更新`）；
  - `verified:false, checked:true`：检查过日志但没发现标记，界面提示“热加载未核实”；
  - `checked:false`：没有检查（例如未提供数据目录）。
- **`verified:true` 也只是日志证据**，不等于模型调用成功；`verified:false` 也不等于失败，可能只是 AstrBot 尚未打印标记，必要时重启 AstrBot 让其生效。

## 7. 安全说明

| 机制 | 说明 |
|---|---|
| 只监听回环 | 服务只绑定 `127.0.0.1`，不监听 `0.0.0.0`，不提供公网访问 |
| 随机端口 | 默认 `MODEL_CONSOLE_PORT=0`，由系统分配；端口写在状态目录锁文件里 |
| 会话令牌 | 每次启动随机生成（或 `MODEL_CONSOLE_SESSION_TOKEN` 复用）；除静态资源外所有接口都要带 `Bearer` 令牌 |
| Host/Origin 校验 | 同时校验请求的 Host、Origin 与跨站标记，拒绝非同源请求 |
| CSP | 页面限制同源脚本/连接，不允许内联脚本 |
| 令牌存放 | 浏览器端只放 `sessionStorage`；URL 片段读取后立即清除；不放 `localStorage` |
| 密钥只在后端 | AstrBot JWT、OpenAPI Key、Agent token 只在 Node 进程内使用，响应只回白名单字段 |
| 静态白名单 | 只暴露页面、样式和前端模块，不开放 `src/`、`state/`、备份目录 |
| DPAPI | Windows 下设备凭据用当前用户 DPAPI 加密保存为 `dpapi:<base64>`；非 Windows 或 DPAPI 不可用时降级明文并留下诊断 |
| 备份先于写入 | 每次应用前先做文件 SHA-256 校验 + SQLite 在线备份 + `quick_check`，任一步失败就不发写入请求 |
| 审计与诊断 | `audit.jsonl` 记录写入事件；`diagnostics.jsonl` 脱敏滚动，不含 token/key/请求体/绝对路径 |
| 远程边界 | HTTP/SSH 永远只读；Agent 默认只读，远程写必须两侧显式开启 |

> 注意：`state/` 目录里的备份包含配置内容，`secrets.json` 在 DPAPI 不可用时可能是明文。请按敏感目录对待。

## 8. 升级与卸载

没有安装器，也没有自动更新：**升级 = 替换程序目录**，用户数据不在程序目录里（默认在 `%LOCALAPPDATA%\AstrBotModelConsole\state`），替换不会动它们。

- 升级：关闭正在运行的控制台窗口 → 用新版本解压出的目录替换旧程序目录（`src/`、`public/`、`node.exe`、`start.cmd`、`docs/` 等）→ 双击新版 `start.cmd`；
- 卸载：关闭控制台窗口（或 `Ctrl+C`，程序会释放单实例锁）→ 删除程序目录；
- 彻底清理：再删除状态目录 `%LOCALAPPDATA%\AstrBotModelConsole\state`——**删除前先确认里面没有你想保留的备份**；`secrets.json` 也在其中；
- 本工具不会修改 AstrBot 的安装目录与 data 目录，卸载本工具不影响 AstrBot。

## 9. 已知限制（请按原文理解，不要乐观解读）

- **保存/回读成功 ≠ 热加载成功，≠ 模型生成成功**；工具没有生成测试。
- 只覆盖**平台级路由视图**；存在会话级/通配符路由时，卡片不能代表任意会话的最终配置（界面会提示）。
- profile/人格显示名**不是**机器人身份；AstrBot 实例标识也不等于 QQ 昵称。
- 插件隐藏 schema、动态调用、数组字段无法完整覆盖；未审查字段始终只读。
- 向量/重排序模型切换需要**单独的索引迁移流程**，本工具只做拦截，不执行迁移。
- 没有跨资源原子事务；AstrBot 也没有原子 CAS，版本双检只能缩小竞态窗口。恢复也是整对象回写。
- 远程写仅限 Agent；热加载只能提供日志证据，不能保证。HTTP/SSH 永远只读。
- DPAPI 不可用时设备密钥会**降级为明文**保存（只有用户目录权限保护），分发/共享机器时需知悉。
- 备份不含插件自己的数据库（例如自学习 `messages.db`）、图片与向量索引；也不做 AstrBot 数据库文件的整体恢复。
- 没有自动回滚；失败后需要按审计/备份人工核对。

## 10. 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 双击 `start.cmd` 闪退 / 提示 `node.exe is missing` | 包不完整 / 只拷贝了部分文件 | 重新解压完整包；核对 `SHA256SUMS.txt` |
| 启动提示 `ANOTHER_INSTANCE_RUNNING` | 同一状态目录已有存活实例 | 复用已打开的窗口，或先关闭旧实例；确认没有残留进程后再启动 |
| 启动提示 `ASTRBOT_DATA_REQUIRED` | 未设 `ASTRBOT_DATA` 且自动发现到 0 个或多个 data 目录 | 用环境变量指定唯一的 data 目录（见 4.2）后重启 |
| 启动报 `INVALID_SESSION_TOKEN` | 手设了 `MODEL_CONSOLE_SESSION_TOKEN` 但格式不对 | 删除该变量；或使用 64 位小写 hex |
| 固定端口启动失败 | `MODEL_CONSOLE_PORT` 指定的端口被占用 | 删除该变量改用随机端口，或换一个端口 |
| 浏览器没自动弹出 | 非 Windows 环境 / 系统未响应 `Start-Process` / 浏览器关联异常 | 手动复制窗口打印的 `url` 到浏览器打开 |
| 页面提示 `ACCESS_DENIED` | 令牌过期/换了实例/端口变了/被跨站请求拦截 | 用最新启动窗口里的令牌重新连接；前端会自动清掉旧令牌并回连接表单 |
| 页面提示 `CONSOLE_UNREACHABLE` / `REQUEST_TIMEOUT` | 控制台进程已退出、电脑休眠、请求超时 | 检查启动窗口是否还在；刷新重试；若刚在保存，先回读确认结果，勿直接重复提交 |
| 保存后 AstrBot 行为没变 | 保存只证明写入+回读；AstrBot 可能未热加载或需要重启 | 看 AstrBot 自己的日志/是否出现重载标记；需要时重启 AstrBot；不要靠反复保存碰运气 |
| 提示 `CONCURRENT_CHANGE` | 配置被其他面板/工具改了，或草稿基线过期 | 在冲突面板核对“我的值 / 服务器当前值”，按“以最新值为基线重新编辑”后重做修改 |
| 提示 `EFFORT_UNVERIFIED_OR_UNSUPPORTED` | 该模型不支持此推理强度，或能力目录读不到 | 打开“模型库”重新查询档位；不要按模型名猜档位 |
| 提示 `VERIFY_FAILED` / `possibly-written` | 写入后回读不一致，或请求中途异常 | 先按审计/备份核对当前真实配置，再决定是否重做；**不要直接重复提交** |
| 提示 `READ_ONLY` | 控制台以只读模式启动 | 关闭后用 `--enable-writes`（或便携包 `start.cmd`）重新启动 |
| 远程 HTTP 设备提示 `DEVICE_UNREACHABLE` / `DEVICE_AUTH_FAILED` / `DEVICE_FORBIDDEN` | 地址不通、Key 错误、Key 权限不足 | 先在目标机确认 AstrBot 与 dashboard 可访问；核对 OpenAPI Key 与其 scope |
| 远程 SSH 设备提示 `DEVICE_SSH_UNAVAILABLE` / `DEVICE_SSH_FAILED` / `DEVICE_PORT_UNKNOWN` | 本机没有 `ssh`、公钥登录不通、远端端口发现失败 | 安装/启用 OpenSSH 客户端并配置免密公钥；确认私钥路径；填写 `dataPath` 让程序从日志发现端口，或直接在地址里写对端口 |
| 远程 Agent 提示 `AGENT_*` / `AGENT_READ_ONLY` | Agent 未启动、端口不对、配对码过期/已用、Agent 未开写 | 重看 Agent 窗口输出的 `url` 与 `pairingCode`；配对码一次性且 10 分钟有效；远程写需要 Agent 端 `--enable-writes` 且 Hub 勾选允许写入 |
| 设备凭据提示 DPAPI 相关失败 | 非 Windows 或 DPAPI 不可用 | 程序会降级明文保存并留诊断；请把状态目录放在受保护的用户目录，不要共享 |
| 杀毒软件把 `.cmd` 报成可疑 | 便携包/构建脚本会调用 `node.exe` 与可见窗口 PowerShell | 用 `SHA256SUMS.txt` 校验完整性；只从可信来源获取；本工具没有隐藏窗口/提权/停进程类脚本 |
| 恢复备份后想撤销 | 没有自动回滚 | 恢复前先看差异；需要时再用更早的备份生成一次恢复计划 |

## 0. 用法与优先级

| 级别 | 定义 | 处理原则 |
|---|---|---|
| **P1** | 主场景明显受损、分发前应修、或有安全/正确性残余风险 | 排进最近 1–2 个迭代 |
| **P2** | 维护性、一致性、体验细节 | 随手修或随相关模块一起改 |
| **Epic** | 需要架构改动的多设备/分发能力 | 单独立项，按设计文档 Phase 推进 |
| **验证缺口** | 不是缺陷，但没验证过 | 有条件就补证据，不能当作已通过 |

每项给了：问题、验收标准、改动面、依赖、规模（S ≤ 半天，M 1–3 天，L > 3 天）。

## 1. P1（10 项）

### P1-01 缓存日志端口与 `cmd_config.json`，避免每次 API 调用重复读盘

- **来源**：REVIEW D09。
- **问题**：`src/gateway.mjs` 的 `call()` 每次都 `stat` 日志、按需扫日志、再读 `cmd_config.json`；一次快照 = 1 次 default + N 个 profile + M 个插件，全部重复文件 IO；2 秒 TTL 对 3 秒轮询几乎每次全量重读。
- **验收**：单次 `/snapshot` 的 `cmd_config.json` 读取 ≤ 1 次、日志扫描 ≤ 1 次；端口或 secret 变化（mtime/长度）后能失效重读；现有测试全绿。
- **改动面**：`src/gateway.mjs`（缓存 + 失效）、`test/gateway.test.mjs`（新建）。
- **依赖**：无。**规模**：M。

### P1-02 推理强度能力查询不能只认回环 `api_base`

- **来源**：REVIEW D10。
- **问题**：`Gateway.efforts()` 要求 `provider.api_base` 是 `127.0.0.1/localhost` 且 http，直连 DeepSeek/Gemini 的 provider 永远返回 `null`，UI 无法调整强度；远程模式下“本机”语义还会错位。
- **验收**：非回环 provider 至少能显示“能力未核实/不支持”的原因，而不是静默失败；支持配置能力来源（provider 声明/本地能力表/用户显式确认）；未知档位仍拒绝。
- **改动面**：`src/gateway.mjs`、`src/engine.mjs`、`public/app.mjs`、`test/engine.test.mjs`。
- **依赖**：P1-01（共用缓存）。**规模**：M。

### P1-03 冲突只有报错，没有差异视图/重载入口

- **来源**：REVIEW D11。
- **问题**：`CONCURRENT_CHANGE` 只弹错误，用户不知道哪个字段被改成什么，只能凭记忆重选。
- **验收**：冲突面板展示 `字段 · 我的基线值 · 服务器当前值`，提供“以最新值为基线重新编辑”；不丢失其他资源的草稿。
- **改动面**：`public/app.mjs`、`public/ui-state.mjs`、`public/styles.css`、`test/ui.test.mjs`。
- **依赖**：无。**规模**：M。

### P1-04 没有备份恢复入口

- **来源**：REVIEW D12。
- **问题**：`engine.rollbackPlan()` 直接抛错；备份有 `manifest.json` 却没有 UI 入口，“备份前置”的承诺没有兑现。
- **验收**：设置页可选备份 → 展示时间/文件数/SQLite 校验 → 生成只读恢复计划 → 预览 → 应用；恢复也走 revision 双检，不覆盖备份之后的他人修改。
- **改动面**：`src/engine.mjs`、`src/server.mjs`、`public/app.mjs`、`test/engine.test.mjs`、`test/server-ui.test.mjs`。
- **依赖**：P1-10（备份目录结构稳定）。**规模**：L。

### P1-05 只读操作与失败前置没有审计，报障不可回溯

- **来源**：REVIEW D13；工作记录“控制台错误提示排查”已出现同类问题。
- **问题**：`audit.jsonl` 只记 apply 事件；快照失败、计划失败、冲突、只读请求都无痕。
- **验收**：结构化诊断日志（脱敏、限频、滚动上限），至少包含时间、操作、错误码、资源/设备；不含密钥、token、绝对路径；设置页可导出支持包。
- **改动面**：`src/server.mjs`、`src/engine.mjs`、新增 `src/diagnostics.mjs`。
- **依赖**：无。**规模**：M。

### P1-06 registry 字段与插件版本强耦合

- **来源**：REVIEW D14。
- **问题**：插件升级改字段名后，“字段不存在”会显示成 `empty-semantics-unverified`（待核实），掩盖真实破损。
- **验收**：绑定行区分“字段缺失/字段存在但为空/空值语义未核实”；卡片展示插件版本或配置版本；字段不存在时给出明确提示。
- **改动面**：`src/registry.mjs`、`src/engine.mjs`、`public/app.mjs`、`test/engine.test.mjs`。
- **依赖**：无。**规模**：M。

### P1-07 平台级路由之外的视图没有提示

- **来源**：REVIEW D15。
- **问题**：只匹配 `platform_id::` 精确路由；存在会话级/通配符路由时，卡片仍按平台级展示，用户可能以为改的就是该会话最终配置。
- **验收**：检测到细粒度路由时，界面显示“本设备存在会话级/通配符路由，卡片仅代表平台级默认”的提示；不假装能解析最终配置。
- **改动面**：`src/gateway.mjs`、`src/identity.mjs`、`public/app.mjs`。
- **依赖**：无。**规模**：S/M。

### P1-08 单机版缺首启引导与设备上下文

- **来源**：REVIEW D17。
- **问题**：页头写死“本机独立运行”，连接区只有“粘贴令牌”；没有首启向导、没有设备健康列表、没有“只读/离线/权限不足”的区分。分发后用户第一次打开不知道从哪开始。
- **验收**：首次运行 4 步向导（发现实例 → 验证连接 → 选择只读/可写 → 完成）；页头显示当前实例/数据目录；状态徽标区分在线/只读/离线/凭据失效。
- **改动面**：`public/index.html`、`public/app.mjs`、`public/ui-state.mjs`、`src/server.mjs`。
- **依赖**：Epic-3（打包）可并行。**规模**：M/L。

### P1-09 Node 运行时与打包分发

- **来源**：REVIEW D18；DESIGN §10。
- **问题**：要求 Node ≥24.22 且依赖 `node:sqlite`；目标用户机器不一定有 Node；SEA 在 Node 24 仍不成熟。
- **验收**：便携 `node.exe` + 应用 zip 可在无 Node 的干净 Windows 启动；Inno per-user 安装器；卸载保留用户数据；产物有 SHA-256。
- **改动面**：新增 `scripts/build-package.mjs`、安装器脚本、README 快速上手；不改运行时代码逻辑。
- **依赖**：P1-08（首启向导）。**规模**：L。

### P1-10 备份产品化剩余项（D05 残留 + RISK-01）

- **来源**：REVIEW D05；P0 审计 RISK-01。
- **问题**：保留策略已实现，但没有每份大小上限、UI 清理入口、占用显示；`pruneBackups` 失败只 `console.error`，磁盘可能无限增长。
- **验收**：设置页显示备份占用/份数，可手动清理并保留最新；单份超过阈值时警告；清理失败写入诊断日志并在 UI 可见。
- **改动面**：`src/backup.mjs`、`src/server.mjs`、`public/app.mjs`、`test/backup.test.mjs`。
- **依赖**：P1-05（诊断日志）。**规模**：M。

## 4. 验证缺口（不是缺陷）

| 缺口 | 现状 | 补证方式 |
|---|---|---|
| 真实浏览器刷新/关标签/无痕 | 只有 `sessionStorage` 纯函数与源码断言 | Playwright：带 token 打开 → 刷新仍连接 → 关标签后失效；截图留证 |
| 屏幕阅读器/键盘全流程 | 静态 a11y 测试 | NVDA/键盘走一遍核心流程，记录问题 |
| 真实 AstrBot 快照 | 冒烟时实例停机，只验证了 `ASTRBOT_UNREACHABLE` | 实例在线时只读 `/snapshot`，记录资源/绑定数 |
| SIGINT/SIGTERM 释放锁 | Windows 下 `child.kill` 不触发 handler | 手工 Ctrl+C 一次，查锁文件是否删除 |
| 并发写/压测 | AstrBot 无 CAS，只做了 revision 双检单测 | 两个控制台并发改同一资源，记录实际竞态窗口 |
| UNC/长路径 | `backupShortId`/`safeApplyResult` 只做了逻辑推演 | 加 `\\server\share` 与 >260 字符路径断言 |
| 备份保留破坏性边界 | 临时目录验证过 | 用真实状态副本跑一次“保留 N 份”，核对删除集合 |

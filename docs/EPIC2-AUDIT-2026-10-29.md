## 2. 独立集成证据（new `test/epic2-integration.test.mjs`）

1. **SSH（注入隧道）**：`createSshTunnel` 注入返回 `{baseUrl:'http://127.0.0.1:4599',close}`，`createHttpGateway` 注入 fake upstream gateway。断言：公开设备视图只含 `ssh.host/user/port`；health 触发隧道并用隧道 baseUrl/apiKey；`/snapshot` 返回真实 Engine 快照（`configVersion` 来自远端配置）且 `writeEnabled:false`；5 秒缓存内不重建隧道；DELETE 返回 `{removed:true}` 并只关闭隧道一次；删除后 snapshot/health 404。
2. **SSH 错误映射**：隧道注入分别抛 `DEVICE_PORT_UNKNOWN`（带绝对路径 details）、`DEVICE_SSH_UNAVAILABLE`（带 token）、`DEVICE_SSH_FAILED`（带 backupId 路径）；`/snapshot` 与 `/devices/:id/health` 均返回 409 稳定码，响应与 `diagnostics.jsonl` 均无路径/token/apiKey。
3. **Agent 真实链路**：真实 `startAgent({stateDir, engine:fakeAgentEngine})` + 真实 `createServer`（默认 `pairAgentDevice`/`createAgentAdapter`，走真实 HTTP）：
   - 缺 pairingCode → 400 `DEVICE_SECRET_REQUIRED`；错误 pairingCode → 经真实 AgentAdapter 映射 409 `AGENT_UNAUTHORIZED`；
   - 正确配对 200，响应/`devices.json` 无 token/pairingCode，`secrets.json` 有 64-hex token 且 `sha256(token)===agent.json.tokenHash`，agent 侧 `pairing:null`（配对码一次性）；
   - 重复设备在配对前被拒：409 `DEVICE_EXISTS`（不会二次消耗配对状态）；
   - `/snapshot?device=` 返回 agent 快照（fake agent 故意返回 `writeEnabled:true`，hub 强制 `false`，RISK-09），5 秒内只读一次；
   - health 仅 `{reachable,latencyMs}`（RISK-10）；DELETE `{removed:true}` 后 404，而 agent 本体 `/agent/v1/health` 仍 200。
4. **RISK 04**：`DIAGNOSTICS_RATE_LIMIT===120`；注入 `diagnosticsLimitPerMinute:3` 后 8 个 403 只写 3 行诊断，事件只含 `code/path/status`。
5. **RISK 05**：`Engine` 快照从 default 配置读 `config_version`（字符串/数字），缺失/对象不猜测为 `null`；`configVersionText` 输出“配置版本 X/未知”；RISK-06 静态断言 UI 文案为“控制台版本”，无“AstrBot 版本”。
6. **RISK 07**：写 7 条 `BACKUP_*` 诊断后 `GET /backups` 返回最近 5 条、最新在前，每项仅 `{code,time,message}`，message 已脱敏；UI 有 `#backup-warnings` 渲染位。
7. **RISK 08**：fake engine 返回含 `internal/enginePath/绝对路径 backupId` 的 restore plan，`POST /restore-plans` 顶层字段被白名单过滤、`changes` 只保留契约四字段、`backupId` 归一为 UUID。
8. **RISK 09/10**：fake 远程 engine 返回 `writeEnabled:true` → hub 响应强制 `false`；health 对非法小写 error 丢弃并收敛为 `{reachable:false,error:'DEVICE_UNREACHABLE'}`，键集合仅 `error/reachable`。

# 模型切换器：设计缺陷评审

评审日期：2026-10-29（UTC+08:00）  
评审对象：`model-console/`（package version `0.1.0`，41 项测试基线）  
评审方法：通读 `docs/HANDOVER.zh-CN.md`、`README.md`、`src/*.mjs`、`public/*`、`test/*`、9 份 `docs/history/2026-10-29-*.md`；核对 AstrBot v4.29.3 本机源码（`C:\Users\<你>\.astrbot_launcher\instances\<实例ID>-…\core\astrbot`）；用 fake gateway 复现关键路径；读取 `state/audit.jsonl` 与备份目录计数。  
**本轮只做评审与设计，不修改功能代码、不写线上 AstrBot 配置。**

## 0. 结论摘要

这个项目最值得保留的不是界面，而是三条纪律：**默认只读、备份前置、计划/回读分离**。它已经是一个能用的“本机单实例模型控制台”，但离“可分发给别人、可管多台 Windows 设备”还差三层：

1. **正确性缺口（P0）**：清空向量/重排绑定可以绕过索引迁移拦截；错误响应把本机绝对路径回传给浏览器。
2. **分发阻断（P0）**：数据目录与 `state/` 路径写死在项目和启动脚本里；会话令牌刷新即丢；备份无限增长；无单实例锁。
3. **架构阻断（P0/P1）**：端口、密钥、备份、审计全部建立在“同机文件系统”假设上。远程化不是加一个 `baseUrl` 参数，而是要新增**连接适配层**与**凭据分层**（详见 `DESIGN-multi-device-2026-10-29.zh-CN.md`）。

评审期间实测：`node --test` 在本沙箱会因 `spawn EPERM` 失败，改用 `node --test --test-isolation=none` 后 **41/41 通过**；`state/` 已有 15 份备份、33 MB；审计记录 15 次 `applied`、覆盖 9 个资源。工具确实被人用过，但主要写入仍发生过在 `.tmp/*.mjs` 脚本里，说明它还不是主写入路径。

## 2. 缺陷清单

严重度定义：**P0** = 正确性 / 安全 / 交付阻断，发版前必须修；**P1** = 主场景或分发体验明显受损；**P2** = 维护性与一致性。

### P0

#### D01 清空向量/重排绑定可绕过索引迁移拦截

- **现象**：`plan()` 的索引迁移拦截写在 `if(change.value)` 分支内，空字符串直接跳过。
- **证据**：`src/engine.mjs:15`；实测（fake gateway）：
  - `{path:'provider_settings.embedding_provider_id', value:''}` → **允许创建计划**
  - 同一路径非空值 → `INDEX_MIGRATION_REQUIRES_SEPARATE_WORKFLOW`
- **影响**：用户把 embedding/rerank 清空后，插件可能在下一次调用时按默认逻辑重建或报错，索引语义断裂；HANDOVER §14.3 已自认，但未修。
- **建议**：空值与有值一视同仁拦截；或者引入显式迁移计划类型（含“先备份插件 DB / 提示重建索引”步骤），不能靠 UI `select.disabled` 兜底。

#### D02 错误响应把本机绝对路径泄给浏览器

- **现象**：`server.mjs` 把 `e.details` 原样展开进 409 响应；`engine.apply()` 的 `details.backupId` 是 `backupState()` 返回的**绝对路径**。
- **证据**：`src/server.mjs:15`、`src/engine.mjs:18`；`src/backup.mjs:6`。
- **影响**：当前只回环还好；一旦远程/多用户/分发，等于把服务器目录结构与用户名暴露给任何持有工具令牌的页面；错误报告也会带出去。
- **建议**：API 只返回 `backupId` 的短 id / basename；绝对路径只进本地审计；错误响应做字段白名单。

#### D03 会话令牌刷新即丢，且没有“重新授权”入口

- **现象**：token 只存内存；`location.hash` 读取后立即 `replaceState` 清掉；刷新页面就回到“粘贴令牌”，而用户通常已经没有那行输出。
- **证据**：`public/app.mjs:35`；HANDOVER §10 也写明“刷新、关闭或重开裸地址会丢失令牌”。
- **影响**：分发后这是第一高频投诉点；用户会去找启动日志里的带 token URL，而这个 URL 本身又不该分享。
- **建议**：把 token 放 `sessionStorage`（刷新存活、关标签清除），或首次 URL token 换取 `HttpOnly; SameSite=Strict` 会话 Cookie；再加“从本次启动输出重新授权”的说明与本地重开脚本。

#### D04 启动脚本硬编码 `ASTRBOT_DATA`

- **现象**：两个 `.cmd` 都把 `C:\Users\<你>\.astrbot_launcher\instances\<实例ID>-…\core\data` 写成默认值。
- **证据**：`start-console.cmd:4`、`start-console-edit.cmd:4`。
- **影响**：换一台机器、换一个 launcher 实例目录就必错；这正是“打包给其他用户”的硬阻断。
- **建议**：首次运行发现 + 可选列表 + 手动路径；配置落到 `%LOCALAPPDATA%`，不再改脚本。

#### D05 `state/` 落在项目目录，且备份无保留策略

- **现象**：`MODEL_CONSOLE_STATE` 默认 `./state`，相对启动 cwd；每次 apply 生成一个 UUID 备份目录，无清理。
- **证据**：`src/server.mjs:16`；`src/backup.mjs:6`；实测 15 份 / 33 MB（含 `data_v4.db`，随库增长线性膨胀）。
- **影响**：装到 `Program Files` 或只读目录时直接写失败；长期使用占盘；分发时用户会把这个目录一起拷走（含凭证）。
- **建议**：状态目录固定到 `%LOCALAPPDATA%\AstrBotModelConsole\`；默认保留最近 N 份 + 每份大小上限 + UI 清理入口；在设置页显示占用。

#### D06 没有单实例锁

- **现象**：`start()` 不检查是否已有实例；`Engine.busy` 只是进程内互斥。
- **证据**：`src/server.mjs:16`、`src/engine.mjs:8`。
- **影响**：双击两次就有两个控制台、两个内存计划、两个备份目录；唯一防线是 revision 双检，而 AstrBot 无 CAS（HANDOVER §7 已承认）。
- **建议**：`state/instance.lock`（含 pid / 端口 / 启动时间）+ 存活探测；第二个实例默认拒绝并提示复用现有窗口。

#### D07 没有“设备 / 操作者”概念

- **现象**：鉴权只有“本次启动随机 token”，审计只有 `apply-start/applied/apply-failed`，没有 actor、没有设备。
- **证据**：`src/server.mjs:14`、`src/engine.mjs:18`。
- **影响**：多设备后无法回答“谁在哪台设备改了什么”；分发给多人时也无法做权限分级。
- **建议**：随连接层引入 `deviceId` 与 `actor`（本机用户名/设备名即可），审计字段扩展；这是多设备设计的前置。

### P1

#### D08 端口发现绑定同机文件系统（远程结构性阻断）

`gateway.mjs:13` 逆读 `<DATA>/logs/astrbot.log` 找 `Starting WebUI at`。远程设备没有这个文件；而磁盘里的 `dashboard.port=6185` 是**死配置**——本机 launcher 实际用环境变量把绑定覆盖成 `127.0.0.1:<随机>`（AstrBot `dashboard/server.py` 环境变量优先，PR #10095）。远程方案必须先解决“怎么知道 baseUrl”，不能读一次 `cmd_config.json` 就假设能连。

#### D09 每次 API 调用都重读日志 stat + `cmd_config.json`

`gateway.mjs:13-14`：每个 `call()` 都 `stat` 日志、按需扫日志、再 `readJSON(cmd_config.json)`。一次快照要读 1 次 default + N 个 profile + M 个 plugin，等于 N+M 次重复文件 IO；2 秒 TTL 对上 3 秒轮询，几乎每次轮询都全量重读。建议进程内缓存 secret/port，用 mtime/长度失效，并把资源读取改为有上限并发。

#### D10 推理强度只对“回环 `api_base`”生效

`gateway.mjs:24` 要求 provider 的 `api_base` 是 `127.0.0.1/localhost` 且 http，才去查 `/models?client_version=0.161.0`。直连 DeepSeek/Gemini 的 provider 永远返回 `null` → UI 无法调整强度；远程模式下“本机”语义还指控制台所在机，必然失真。建议能力来源分层：provider 声明 → 本地能力表 → 用户显式确认，不能只有反代一条路。

#### D11 冲突只报错，没有差异视图/重载入口

`prepare()` 遇到 `CONCURRENT_CHANGE` 只弹错误；用户不知道哪个字段被谁改成了什么，只能凭记忆重新选。建议冲突面板展示 `baseValue → 当前值` diff，提供“以最新值为基线重新编辑”。

#### D12 没有恢复/回滚入口

`engine.rollbackPlan()` 直接抛 `ROLLBACK_USES_BACKUP_AND_NEW_REVIEWED_PLAN`；备份有 `manifest.json` 但没有 UI 读取。分发工具没有“从备份生成可审查的恢复计划”，用户出事只能手工改文件——这与“备份前置”的承诺不匹配。

#### D13 只读操作与失败前置无审计

审计只记 apply 事件；快照失败、计划失败、冲突、只读请求都无痕。工作记录第 3 条（`2026-10-29-控制台错误提示排查.md`）已经出现“用户只说操作未完成，无法还原现场”。建议加脱敏的结构化诊断日志（限频、上限、滚动）。

#### D14 registry 字段与插件版本强耦合

`src/registry.mjs:4-9` 是手工审查清单。插件升级改字段名后，`bindingRows()` 会把“字段不存在”显示成 `empty-semantics-unverified`（待核实），掩盖真实破损。建议增加“字段存在性”状态，并在 UI 展示插件版本/配置版本。

#### D15 平台级路由之外的视图会误导

`identity.mjs:4-5` 只匹配 `platform_id::` 精确路由。若设备存在会话级/通配符路由，卡片仍按平台级展示，用户可能以为改的就是该会话最终配置。HANDOVER §3.3 已声明，但 UI 没有“本设备存在细粒度路由”的提示。

#### D16 可访问性不达标

- 对比度（实测）：`--muted #68748a` on `#f6f7fb` = **4.40:1**（< 4.5）；`.eyebrow #8790a5` = **2.99:1**；`.rail-label #97a0b2` = **2.63:1**。
- 字号：`.path` 用到 **8px/9px**；全站 10px 多处。
- 响应式：`@media(max-width:920px)` 把 `.rail nav span` 设为 `display:none`，导航只剩 `◫ ▤ ▦ ◇` 符号，链接没有 `aria-label`（`public/index.html:3`）——窄屏下屏幕阅读器读到的是无意义符号。
- 建议：调深次要色（`#55607a` = 5.87:1、`#5f6a80` = 5.08:1）；正文最小 12px；图标导航补 `aria-label`；窄屏提供 tooltip。

#### D17 缺少设备上下文与首启引导（多设备/分发的前置 UI 缺口）

页头写死“本机独立运行”，连接区只有“粘贴令牌”。没有设备切换、没有设备健康列表、没有首启向导、没有“只读/离线/权限不足”的区分。分发后用户第一次打开不知道从哪开始。

#### D18 Node 版本门槛高

`package.json` 要求 `node >=24.22`，且备份依赖 `node:sqlite`。目标用户机器不一定有 Node；SEA 在 Node 24 仍是 `Stability 1.1`，只吃单个 CJS，与当前纯 ESM + 磁盘静态资源冲突。打包必须自带运行时（详见设计文档 §10）。

## 3. 现有设计的优点（不要改掉）

1. **写默认关闭**：`--enable-writes` 是分发工具的正确默认。
2. **备份硬阻断**：备份失败不写，且有 SQLite `quick_check`；这是很多管理面板缺的。
3. **revision + 双检 + `possibly-written`**：承认 AstrBot 无 CAS，失败时要求人工核对而不是自动重试。
4. **身份四对象分离**与**default 是合法目标**：两次错误纠正换来的规则，值得保留为产品语义。
5. **展示视图不改变保存资源**：`profileViews()` 用 bot id 做展示 key，草稿仍按 `kind/id/path`，这个设计在多设备下同样成立。
6. **限制写进文档**：HANDOVER §14 的缺口清单是接手友好的资产。

## 5. 不改架构能做到什么

- **能**：修完 P0 + 一部分 P1 后，它可以成为一个“本机单实例、可分发给单机用户”的工具（便携 zip + 首次配置 + 令牌刷新存活 + 备份保留/恢复）。
- **不能**：管远端设备。`gateway.mjs:13` 的文件系统假设、`gateway.mjs:18` 的 `127.0.0.1`、`server.mjs:13` 的 Host 校验、`backupState(data,…)` 的本地路径共同决定：远程化必须新增连接层与凭据层，属于架构改动。
- 具体改造方案见 [`DESIGN-multi-device-2026-10-29.zh-CN.md`](DESIGN-multi-device-2026-10-29.zh-CN.md)。
